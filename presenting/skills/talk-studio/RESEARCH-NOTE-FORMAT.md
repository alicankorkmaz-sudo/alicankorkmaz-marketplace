# Research Note Format

One note per research question, in `./research/NNNN-slug.md`. Notes are the depth behind `FACTS.md` and the material for the Q&A.

## Structure

```md
# NNNN — {The question, as the user asked it}

**Date:** {YYYY-MM-DD} · **Asked by:** user | follow-up from NNNN
**Relevance:** spine | support | if-asked | out

## Short answer
{Three to five sentences. What the evidence says, how strong it is.}

## Findings
- **{Source name}** ({type, date}): {what it found or argued}. {Number with population.} → F0xx
- **{Source name}** ({type, date}): {…} → F0yy

## Disagreements and caveats
- {Where sources conflict, and why (different measures, populations, dates).}
- {Limits: vendor-run, self-reported, secondary only, not verified at primary.}

## For the talk
- {How this could be used on stage, if at all: an opening, a slide, a fair-framing caveat, an answer for the Q&A.}

## Open threads
- {What is still unknown or worth checking.} → OPEN-QUESTIONS
```

## Rules

- **The question in the user's words** as the title, so they recognise it later.
- **Every finding links its source** and the `FACTS.md` row it produced.
- **Disagreement is a finding.** Don't average conflicting numbers; explain them.
- **Relevance is a judgement, not a filter.** An `if-asked` note is as carefully sourced as a `spine` note; it just doesn't go on a slide.
- **The user's sources first.** When the user brings a source, read it and note what it actually says before looking elsewhere.
