# BASELINE.md Format

`BASELINE.md` is the output of Phase 1 (Foundation Assessment). It is the mentor's honest snapshot of where the user stands and how they think. It is rewritten — not appended — whenever the picture changes materially (mission shift, learning done elsewhere, a run of challenges that reveals the original read was wrong).

## Template

```md
# Baseline: {Topic}

_Last assessed: {date}, session {n}_

## Current level
{One or two sentences. Where the user sits relative to the mission's "mastery looks like" bullets. Be honest, not kind.}

## Strengths
- {Something the user demonstrated — with the evidence that showed it}

## Gaps
- {Something the user lacks or got wrong — with the evidence}

## Thinking style
{How the user reasons: top-down or bottom-up, pattern-matches or derives, jumps to answers or explores, over-trusts or under-trusts intuition. Two or three sentences. This shapes how challenges are framed and how feedback lands.}

## Likely misconceptions to watch
- {A belief that, if held, would derail later topics. Mark as confirmed or suspected.}

## Diagnostic questions asked
1. {The question, and a one-line summary of the answer}
2. {…}
```

## Rules

- **Evidence, not impressions.** Every strength and gap cites what the user actually said or did.
- **Never inflate.** Overstating the level ruins the zone of proximal development for every later session.
- **Thinking style is the point.** Two users with the same knowledge can need very different challenges. Capture how they think.
- **Rewrite in place.** History lives in learning records, not here. This file is always the current best read.
- **Narrative here, levels in the map.** Per-skill levels and their evidence live in `SKILL-MAP.md`; this file holds the overall picture and the thinking style. Keep the two consistent when either changes.
