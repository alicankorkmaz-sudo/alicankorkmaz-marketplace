# GLOSSARY.md Format

`GLOSSARY.md` is the canonical language for this workspace. Knowledge blocks, challenges, feedback, reference cards and learning records all adhere to it. Building it is itself learning: compressing a concept into a tight definition is evidence the user understands it.

## Structure

```md
# {Topic} Glossary

{One or two sentences describing the scope.}

## Terms

**{Term}** _(en: {English term, if the working language differs})_:
{One or two sentences. What it IS, not how to do it.}
_Avoid_: {aliases the workspace will not use}

## Principles

**{Transferable principle from a challenge}**:
{One sentence. Where it applies beyond the original challenge.}
_First met in_: challenges/NNNN
```

## Rules

- **Add a term only when the user can use it correctly.** The glossary records compressed knowledge; it is not a dictionary to learn from.
- **Principles get their own section.** The transferable principles surfaced in Phase 2 feedback (c) accumulate here; Phase 3 synthesis draws on this section.
- **Be opinionated.** Pick the best word; list the rest as aliases to avoid.
- **Keep definitions tight.** One or two sentences.
- **Use the glossary's own terms inside definitions.**
- **Flag ambiguities explicitly.** "In this workspace, X always means …"
- **Revise as understanding deepens.** Update in place.
