# MISSION.md Format

`MISSION.md` lives at the workspace root. It captures the _reason_ the user is pursuing mastery of this topic. Every decision — what to diagnose, which challenge to issue next, which resources to surface, which mental models to teach — traces back to it.

## Template

```md
# Mission: {Topic}

## Why
{1–3 sentences. The concrete real-world outcome. What changes in the user's life or work when they have this? Push past "understand X" to the underlying result.}

## Mastery looks like
- {A specific, observable thing the user will be able to do, at the level a practitioner would recognise}
- {Another}

## Constraints
- {Time, budget, prior commitments, learning preferences, anything that bounds the approach}

## Out of scope
- {Adjacent topics the user explicitly does not want to chase now, protecting the zone of proximal development}
```

## Rules

- **One mission per workspace.** Two unrelated topics means two workspaces.
- **Concrete over abstract.** "Pass the CKA exam in November" beats "learn Kubernetes". "Negotiate my next contract 20% higher" beats "get better at negotiation".
- **Push back on vagueness.** If the user cannot say why, interview them before writing anything. A bad mission is worse than no mission.
- **Revise when reality shifts.** When the goal moves, update this file and write a learning record. Confirm with the user first.
- **Keep it short.** Past one screen, it has stopped being a compass and become a plan.
